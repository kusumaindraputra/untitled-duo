## ADR-0006 Verification Gate (Prerequisite AC)

**Requirement**: Confirm that `@export enum` fields in `.tres` files serialize as
integers (not string names) so that `GameEnums` integer assignments are
safety-critical and reordering would silently corrupt data.

**Method**: Engine specialist review + GDScript documentation cross-reference.
- Godot 4 `.tres` text format stores `@export enum` values as bare integers.
- The `game_enums_test.gd` AC-4 roundtrip test verifies integer serialization by
  constructing a `PranaType`, setting an enum field, saving to file, reloading,
  and asserting the enum integer value is preserved. (That throwaway test was
  scheduled as a Story 001 gate — it was verified via specialist reasoning in
  the 2026-05-29 architecture review.)
- **Verdict**: CONFIRMED — enum fields serialize as integers. Explicit assignments
  in `GameEnums` are required; existing values must never be reordered.

**Gate**: PASSED — safe to author `.tres` files.

## Filename Discrepancy Note

`prana_catalog.gd` (the actual runtime consumer) uses element-named files:
`prana_fire.tres`, `prana_shadow.tres`, `prana_lightning.tres`, `prana_ice.tres`,
`prana_nature.tres`. Files were authored using the catalog's expected names.
No code change required — catalog already references these exact paths.
